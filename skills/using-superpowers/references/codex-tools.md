# Codex host capabilities

Use the current host's exposed tools and permissions. A remembered CLI version,
configuration entry, or this reference cannot establish live capability.

## Delegation and waiting

Use delegation only when authorized and useful. If it is unavailable, use inline
execution and disclose the independence limit of author self-review. Do not edit
host configuration to enable delegation as a side effect of an ordinary task.

Follow the actual dispatch schema. Preserve inherited model/effort unless the
host or user explicitly authorizes an override; never copy a model identifier
from an old session or template. An available model is not authorization to use it.
For a fresh bounded child, supply the task, relevant paths, and current evidence;
include broader history only when needed. Use follow-up/resume tools only if they
are exposed by this host. Do not invent lifecycle commands.

While a child runs, continue independent work. When idle, use an event-aware wait
within the host's supported bounds and communication requirements. Completion
notifications, timeouts, and missing reports require fresh state inspection,
not duplicate dispatch. A wait timeout is not task completion or a reason to
change model/security policy.

## Workspace and review identity

Inspect branch and worktree state before creating or cleaning isolation. Prefer
Orca/native ownership where available. A linked worktree, detached HEAD, and a
sandbox denial are distinct facts; do not infer permissions from branch state.

Review the recorded task BASE..HEAD, or the verified branch merge-base..HEAD for
a whole PR. Inspect relevant uncommitted changes separately. Never default a
multi-commit task to HEAD~1. Use native finishing controls when the current host
requires them; otherwise continue the authorized Git/CLI workflow. Do not commit,
push, merge, install, upgrade, or delete merely because a helper suggests it.

For optional tool selection and evidence limits, read
[tool discovery and evidence](tool-discovery-and-evidence.md) only when that
choice affects the task.
